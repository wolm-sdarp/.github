# Настройки организации: метки и шаблоны issues

Папка относится к репозиторию `wolm-sdarp/.github` (локально — `gh-profile/`). Спецификация системы типов и меток — `documentation/content/gh-issues-docs.md`.

| Файл                                            | Назначение                                                                           |
| ----------------------------------------------- | ------------------------------------------------------------------------------------ |
| `settings/labels.yml`                           | Источник истины для меток: имена, цвета, описания, наборы репозиториев, устаревшие метки |
| `settings/apply-labels.py`                      | Приводит метки репозиториев организации к `labels.yml`                               |
| `.github/ISSUE_TEMPLATE/*.yml`                  | Формы issues для всех репозиториев организации (каждая форма задаёт тип задачи)      |
| `.github/ISSUE_TEMPLATE/config.yml`             | Настройки выбора шаблонов (пустые issues отключены)                                  |

## Метки

Требуется [GitHub CLI](https://cli.github.com/) (`gh`), выполненный `gh auth login` и право записи в репозитории организации. Python 3 — без сторонних библиотек.

```bash
python3 settings/apply-labels.py --check                       # проверить labels.yml (GitHub не нужен)
python3 settings/apply-labels.py                               # план для всех репозиториев, ничего не меняется
python3 settings/apply-labels.py --repo book1                  # план для одного репозитория
python3 settings/apply-labels.py --apply                       # создать, обновить, переименовать метки
python3 settings/apply-labels.py --apply --delete              # то же + удалить устаревшие метки
```

Что делает скрипт:

- **создаёт** отсутствующие метки и **обновляет** цвет и описание у существующих;
- **переименовывает** метки по `aliases` (например, `documentation` → `tech:docs`): задачи остаются привязанными;
- **удаляет** метки из списка `delete` только с `--apply --delete`; перед удалением показывает, сколько issues и PR используют метку, и для используемых спрашивает подтверждение (`--yes` отключает вопрос);
- **не трогает** метки из списка `ignore` (их создаёт Dependabot) и любые другие неописанные метки — только перечисляет их (например, опечатку `gihub_actions`);
- пропускает репозитории, которых ещё нет в организации (`manim`, `wolm-sdarp.github.io`);
- безопасен при повторном запуске: если всё уже приведено в порядок, изменений не будет.

Рекомендуемый порядок первого применения: запуск без флагов → просмотр плана → `--apply` → проверка задач, которые ссылаются на устаревшие метки → `--apply --delete`.

### Как менять систему меток

1. Изменить `labels.yml` (формат — см. комментарии в начале файла); запустить `--check`.
2. Если метка переименовывается, записать прежнее имя в `aliases`.
3. Если метка выводится из обращения, перенести её имя в список `delete` после переноса задач.
4. Записать изменение в раздел «История изменений» документа `gh-issues-docs.md`.
5. Выполнить dry-run, затем `--apply`.

Новый репозиторий добавляется в нужный набор в `repo_sets`.

## Формы issues

Файлы из `.github/ISSUE_TEMPLATE/` после публикации в репозитории `.github` действуют во всех репозиториях организации, **где нет собственной папки `ISSUE_TEMPLATE`** (она перекрывает общую). В `documentation` лежат шаблоны, унаследованные от Quartz, — их нужно удалить, чтобы заработали общие.

Перед использованием форм проверьте:

- в организации созданы все типы, указанные в `type:` форм (Mistake, Editing, Writing, Learning Design, Assessment, Bug, Feature, Maintenance, Research, Epic, Task); если тип не создан, форма его не назначит;
- метки `status:needs-triage` и другие созданы в репозиториях (скрипт выше);
- ссылка на Discussions в `config.yml` раскомментирована, когда Discussions включены.

Порядок форм в списке выбора задают числовые префиксы в именах файлов: 01–02 — для читателей и рецензентов, 10–12 — содержание и методика, 20–22 — техника, 30–31 — исследования и эпики, 99 — «Другое».
